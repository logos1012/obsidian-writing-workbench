# 릴리스 검증 기록

현재 상태: 개발 빌드. 프로덕션 인수 검증 진행 전.

## 자동 검증

- [x] TypeScript strict 빌드
- [x] 제안 수신·거절이 원고를 변경하지 않음
- [x] 개별 수락과 명시적 파일 저장
- [x] 사용자 편집 이후 오래된 제안 차단
- [x] 중복·겹침·없는 구절 오적용 차단
- [x] 외부 수정 시 파일 덮어쓰기 차단
- [x] 저장 전 기록 실패 시 파일 쓰기 차단
- [x] 파일 쓰기 후 기록 실패 시 중단된 저장 복구
- [x] 버전 복원이 현재 작업 사본을 보존
- [x] 제공자 전환 시 공통 맥락 전달
- [x] 승인 전 문체 원칙 비적용
- [x] 원고 작성 없는 인터뷰, 다중 질문 거부
- [x] 임의 HTML·위험 URL의 실행 차단
- [x] CLI timeout·취소·시작 실패·출력 한도 처리
- [x] JSON 쓰기 순서·백업·손상 복구

## 실제 환경 검증

- [x] 실제 Claude Code 구조화 인터뷰·검토 응답
- [x] 실제 Codex 구조화 인터뷰·검토 응답
- [x] 두 제공자의 웹 검색 허용 요청에서 출처 포함 응답 수신 (출처 정확도 전수 검증은 별도)
- [ ] Obsidian에서 설치·활성화·기존 노트 연결·새 글 생성
- [ ] macOS 한글 IME 조합·커서 보존
- [ ] 밝은/어두운 테마·좁은 창·키보드 접근
- [ ] 앱 종료·재시작 이후 작업 복원
- [ ] 원고를 다른 탭/앱에서 편집할 때 충돌 UX
- [ ] 플러그인 업데이트 후 데이터 유지
- [ ] 파일 삭제·오프라인 파일 이동 복구 UX
- [ ] 긴 원고·다수 작업 기록·동기화 충돌 검증

도구 제한: 이번 작업에서 Computer Use의 Obsidian 앱 접근이 승인되지 않아 실제 앱 화면 검증을 수행하지 못했다. UI 자동 테스트는 jsdom에서 수행했다.

2026-10-26 연결 검사: Claude Code 2.1.310과 Codex 0.164.0에서 합성 문장을 사용했다.
인터뷰 응답은 두 제공자 모두 통과했다. 자료 검색을 허용한 검토에서는 Claude가 제안 2개/출처 2개,
Codex가 제안 1개/출처 2개를 반환했으며 구조화 형식과 실제 원고 구절 일치를 확인했다.
사용자의 원고·이미지·볼트 자료는 연결 검사에 사용하지 않았다.

배포 산출물은 `dist/writing-workbench/`에 생성한다. `main.js`, `manifest.json`, `styles.css`,
설치 설명, 설계·검증 문서, 파일 체크섬을 포함한다. 런타임 의존성 보안 감사 결과 알려진 취약점 0건.

## 릴리스 차단 조건

실제 앱과 CLI 검증 없이 프로덕션 완료를 표시하지 않는다. 테스트 실패, 원고 손실 가능성,
미검증 마이그레이션, 깨진 설치 패키지는 배포 차단 사유다. 기존 사용자의 state/ 및 data.json은 업데이트로 덮어쓰지 않는다.
