# 글결 제품 설계

상태: 구현 진행 중. 프로덕션 준비 완료를 의미하지 않는다.

## 확정 요구사항

- LinkedIn을 먼저 지원하고 다른 매체로 확장한다.
- Obsidian 안에서 대화하며 macOS의 Claude Code / Codex CLI를 사용한다.
- 같은 글의 대화·메모·원고·선택 기록을 유지하며 제공자를 바꾼다.
- 아이데이션은 사용자에게 한 번에 하나씩 질문하는 인터뷰다.
- 자료 탐색은 사용자의 요청 또는 제공 자료를 기반으로 한다. 임의로 전체 볼트를 수집하지 않는다.
- AI는 주제·관점·개요를 정리한다. 초안은 사용자가 직접 작성한다.
- 초안 검토는 전체 진단과 문장별 제안을 함께 제공한다.
- 문장 변경은 사용자의 개별 수락 이후 반영한다.
- 기본 평가 기준에 사용자 문체 원칙을 더한다. 새 원칙은 사용자가 승인해야 지속 적용한다.
- 원고 보존, 복원, 실패·취소·충돌 처리, 테스트, 설치·배포 절차를 출시 조건에 포함한다.

## 작업 흐름

1. 빈 원고를 만들거나 현재 Markdown 원고를 작업실에 연결한다.
2. 인터뷰에서 경험을 이야기한다. AI는 하나의 질문과 갱신할 메모를 제안한다.
3. 관점·독자·근거·반론·생각의 이동·표현 원칙·개요를 정리한다.
4. 사용자가 원고를 작성한다. 작업 중 사본은 복구할 수 있게 보관한다.
5. 전체 검토를 요청한다. 외부 자료 검색은 해당 요청에서 명시적으로 켠다.
6. 진단과 변경 전후, 수정 이유, 참고 출처를 확인한다.
7. 제안을 하나씩 수락·거절한다. 원고가 달라졌으면 오래된 변경을 자동 적용하지 않는다.
8. LinkedIn 형태의 데스크톱·모바일 미리보기를 확인한다. 게시와 정확한 피드 접힘 재현은 별도 범위다.
9. 변경 이력을 열어 이전 원고를 확인하거나 새 버전으로 복원한다.

## 화면

상단에 연결 원고·저장 상태·제공자·중지를 표시한다. 세 영역은 글쓰기 작업을 기준으로 나눈다.

```text
원고 이름                         Claude Code / Codex       저장
┌──────────────────┬─────────────────────┬─────────────────────┐
│ 방향 메모         │ 원고 / 미리보기      │ 인터뷰 / 검토 / 이력 │
│ 관점·독자·근거    │                     │ 질문 또는 전체 진단  │
│ 반론·전개·개요    │ 사용자 원고          │ 문장별 제안·출처     │
│ 승인된 문체 원칙  │                     │ 수락 / 거절          │
└──────────────────┴─────────────────────┴─────────────────────┘
```

좁은 창에서는 세 영역을 세로로 배치한다. Obsidian 테마 변수와 기본 글꼴을 사용한다.
원고는 읽기 편한 행 길이와 여백을 사용하고, 검토에서만 빨강·초록을 쓴다. 색상 외에도 삭제/추가 레이블을 제공한다.

디자인 기준: 밝은 기본값 #ffffff(원고), #f5f6f8(보조), #20242b(본문), #536b9f(강조),
#a43440(삭제), #267044(추가). 실제 색상은 테마 변수에 맞추며 어두운 테마도 지원한다.
일반 대시보드처럼 카드들을 반복하지 않고 메모·원고·대화의 역할에 맞는 밀도를 유지한다.

## 0.1.1 화면 개선

사용자 피드백: 제안 결정 뒤 스크롤 초기화, 고정된 세 영역 너비, 그대로 보이는 Markdown 기호,
항상 입력창인 메모와 약한 항목 구분, CLI의 실행 여부가 불분명함.

기존 테마 색·글꼴을 유지하고 메모는 제목에 짧은 강조선과 굵기를 주며 내용은 읽기용 문서로 표시한다.
수정할 항목만 명시적으로 편집한다. 칸마다 장식적인 카드를 추가하는 대신 제목·간격·구분선으로 구획한다.
세 영역은 두 개의 드래그 구분선으로 조절하고 너비를 보존한다. 좁은 작업실에서는 세로로 배치한다.
AI 실행 배너는 작업실 상단에 고정된 흐름 안에 표시하며 완료율은 추정하지 않는다.
실제 프로세스 시작/응답 처리 이벤트, 경과 시간과 중지 버튼으로 상태를 알린다.
스크롤은 DOM 갱신 전 복원 정보를 잡고 처리 중인 제안을 화면 기준점으로 유지한다.

## 합리적인 초기 기본값

- 기본 제공자 Claude Code, 작업 중 언제든 Codex로 전환 가능. 자동 동시 호출 없음.
- 모델명은 CLI 기본값을 사용하며 설정에서 변경할 수 있다.
- 인터뷰 단계에서는 원고 생성 금지. 리뷰는 최대 12개 제안으로 제한한다.
- 기본 기준: 주장 명확성, 논리, 사실·근거, 독자 가치, 문체·가독성. 근거 없는 숫자 점수 없음.
- LinkedIn 게시 자동화 및 과거 성과 수집은 첫 버전에 포함하지 않는다.
- 원문 보호는 프롬프트뿐 아니라 도구 제한과 적용 계층의 충돌 검사로 구현한다.

## 출시 범위와 단계

1. 기반: 상태 스키마, 원고 연결, 복구 가능한 저장, UI, 버전 기록.
2. AI: 두 CLI 어댑터, 구조화 응답, 전환, 취소·시간 제한, 인터뷰·리뷰·출처.
3. 신뢰성: 잘못된 응답, 오래된 제안, 중복 문장, 파일 이동, 저장 실패, 재시작 복구 테스트.
4. 배포: 설치용 파일, 버전 호환표, 실제 Obsidian과 두 CLI로 인수 검증.

프로덕션 완료 판단은 docs/release-checklist.md의 검증 결과로 한다. 미검증 항목은 완료로 표시하지 않는다.

## 0.1.2 피드백 반영

- 문장별 수락 취소: 검토 원문의 겹치지 않는 범위로 재구성하여 다른 수락을 유지한다. 수락 뒤 수동 변경이 있으면 자동 취소를 중단한다. 취소 전 작업 사본과 수락·거절·취소 결정 이력을 남긴다.
- 메모는 반복된 수정 버튼 없이 더블클릭/Enter로 편집한다. 편집 중에만 저장·취소를 표시한다.
- 인터뷰를 **글감 찾기**로 표시한다. 기능 안내, 사용자 답변과 AI 요약, 이번 질문을 분리한다. 이전 대화는 접어서 볼 수 있다.
- 미리보기는 #f3f2ef 피드 배경, 흰 게시물, #0a66c2 브랜드 색으로 구성한다. 밝은 LinkedIn 피드의 글 가독성을 테마와 독립적으로 확인한다. 데스크톱 카드 여백과 모바일 하단 탐색 표시를 구분하고 실제 게시 기능은 넣지 않는다.

저장 형식은 대화의 작업 종류·질문과 결정 이벤트를 추가한다. 기존 프로젝트에는 기본값을 적용하며 대화 본문을 보존한다. 이전 대화는 종류를 알 수 없어 글감 찾기에 그대로 남긴다. 새 버전에서 저장한 기록을 이전 플러그인 버전으로 다시 읽는 다운그레이드는 지원하지 않는다.

## 0.1.3 이름과 저장 위치

표시 이름은 **글결**로 변경한다. 내 생각과 문체를 살리며 글을 다듬는 방향이며 LinkedIn 이후 다른 글쓰기에도 사용할 수 있는 이름이다. 이전 설치 호환성을 위해 내부 식별자는 writing-workbench로 유지한다.

새 글 저장 폴더는 설정에서 직접 경로 입력 또는 볼트 폴더 선택 후 저장한다. 변경은 새 글에만 적용하며 기존 노트 이동은 수행하지 않는다. 신규 기본값은 글쓰기, 이전 Writing Workbench 폴더가 있으면 설정 변경 전까지 유지한다. 빈 경로는 볼트 최상위다. 설정 저장 시 폴더를 만들지 않고 새 글 생성 시 필요한 부모부터 생성한다.
