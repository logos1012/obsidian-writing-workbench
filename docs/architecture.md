# 기술 설계

## 경계

- UI: Obsidian ItemView. 원고 편집, 인터뷰, 검토, 기록을 하나의 작업실로 제공한다.
- 도메인: Obsidian에 의존하지 않는 상태·검증·제안 적용·프롬프트 모듈.
- 문서 포트: Obsidian Vault.process를 통한 원자적인 비교 후 저장. 외부 수정과 충돌하면 덮어쓰지 않는다.
- 저장소: 볼트 플러그인 폴더의 프로젝트별 JSON. 임시 파일 쓰기/동기화/rename, 이전 파일 백업, 스키마 검증.
- 실행기: 로컬 실행 파일을 shell 없이 spawn. 입력은 stdin. 출력 제한·시간 제한·취소·프로세스 그룹 종료.
- 제공자: Claude print JSON과 Codex exec JSON schema를 공통 응답 모델로 변환.

## 컨텍스트 이동

CLI 내부 세션 ID에 의존하지 않는다. 현재 원고, 방향 메모, 공통 대화, 승인된 원칙,
수락·거절 기록을 매 요청에 전달한다. 따라서 제공자를 바꿔도 작업실이 가진 맥락은 동일하다.
컨텍스트가 설정 한도를 넘으면 조용히 잘라내지 않고 오류를 표시한다.

## 원고 변경

AI는 파일 편집 도구를 받지 않는다. 작업실은 문장 제안만 받는다.
제안 원문은 리뷰 스냅샷에 정확하게 한 번 나타나야 한다. 중복 문장은 범위를 넓히도록 재검토한다.
수락 전 현재 작업 사본이 리뷰의 기대 원고와 같은지 확인한다. 수락된 변경들만 누적하여 기대 원고를 계산한다.
겹치는 제안이나 사용자의 중간 편집은 충돌로 처리한다.
파일 저장은 Vault.process의 최신 문자열과 기준 문자열을 비교하고 실패 시 사용자의 사본을 보존한다.
변경 작업 전후를 기록해 복원은 이전 기록 삭제가 아닌 새 버전 생성으로 수행한다.

## 자료와 실행 환경

사용자가 입력한 자료와 선택한 참고 노트만 프롬프트에 넣는다.
외부 검색은 요청별로 명시적으로 허용한다. 검색 비허용 시 웹 도구를 끈다.
CLI는 별도 임시 디렉터리에서 실행하며 볼트를 작업 디렉터리로 넘기지 않는다.
사용자 CLI 로그인은 유지하되 프로젝트별 자동 도구·MCP·훅이 작업에 끼어들지 않도록 실행 설정을 제한한다.
CLI를 쓴다는 것은 모델이 로컬에서 실행된다는 뜻은 아니다. 요청 내용은 선택한 제공자의 서비스로 전달된다.
응답 URL은 http/https만 허용한다. 모델 응답은 HTML로 삽입하지 않는다.
