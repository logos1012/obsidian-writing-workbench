# 글결

글결(기존 Writing Workbench)은 옵시디안에서 대화로 글감을 찾고, 직접 쓴 LinkedIn 초안을 AI와 검토하는 데스크톱 플러그인입니다.
현재 버전은 **0.1.3 개발 빌드**입니다. 실제 Obsidian 인수 검증이 끝나기 전까지 프로덕션 릴리스로 취급하지 않습니다.

## 구현된 흐름

- 글감 찾기에서 한 번에 한 질문씩 대화 → 관점·독자·근거·반론·개요 정리
- 사용자가 직접 초안 작성
- 전체 진단 + 문장별 변경 제안, 개별 수락·거절·수락 취소
- Claude Code / Codex 전환과 공통 대화·메모·결정 맥락 전달
- 요청별 외부 검색 선택, 사용자 지정 참고 노트·자료
- 승인한 문체 원칙만 다음 글에도 적용
- 데스크톱·모바일 형태의 LinkedIn 예상 미리보기와 복사
- 작업 사본 저장, 원고 저장 시 외부 수정 감지, 버전 복원, 중단된 파일 저장 복구
- 보내기 전 인터뷰 답변 보관, 원고가 삭제된 경우에도 작업 기록 다시 열기
- 수락·거절 후 읽던 위치 유지, 세 영역의 폭 조절과 저장
- AI 답변·메모·진단·이력의 Markdown 서식 표시
- 읽기 중심 방향 메모와 더블클릭 편집·저장·취소
- AI 실행 상태, 경과 시간, 요청 중지 표시

AI 제안을 수락하면 **작업 사본**에 반영됩니다. `원고 저장`을 눌러 연결된 Markdown 파일에 저장합니다.
작업 사본은 별도 기록으로 자동 보관됩니다. 다른 앱에서 파일을 바꿨다면 덮어쓰지 않고 충돌을 알립니다.
`파일에서 다시 불러오기`는 최신 파일을 불러오며 기존 작업 사본은 이력에 남깁니다.

## 개발

Node.js 22 이상:

```sh
npm ci
npm run check
npm run package
```

`npm run dev`는 플러그인 번들을 감시 빌드합니다. `npm run smoke:cli`는 실제 로그인된 CLI를 호출하는 유료/구독 사용량이 발생할 수 있는 선택적 검사입니다. 일반 테스트는 AI를 호출하지 않습니다. 연결 검사는 합성 문장만 전달합니다.

자료 검색과 검토 연결까지 확인하려면 `npm run smoke:cli -- --review --research`를 사용합니다.

## 설치와 사용

### BRAT으로 설치

1. Obsidian의 커뮤니티 플러그인에서 **BRAT**를 설치하고 켭니다.
2. BRAT 설정에서 **Add beta plugin**을 선택합니다.
3. 저장소 주소 `https://github.com/logos1012/obsidian-writing-workbench`를 입력합니다.
4. 버전 **0.1.3**을 선택하거나 최신 버전을 선택해 설치합니다.
5. 글결을 활성화하고 아래의 CLI 설정을 완료합니다.

저장소가 비공개인 경우에는 BRAT에 이 저장소의 Contents 읽기 권한이 있는 GitHub 토큰을 먼저 설정해야 합니다.
BRAT은 GitHub 릴리스에 첨부된 `main.js`, `manifest.json`, `styles.css`를 설치합니다. 소스 ZIP을 별도로 풀 필요는 없습니다.

이미 설치했다면 BRAT에서 업데이트를 확인하세요. `0.1.0`으로 버전을 고정한 경우 최신 버전 또는 `0.1.3`로 변경합니다.

### 새 글 저장 폴더

**설정 → 글결 → 새 글 저장 폴더**에서 경로를 입력하거나 `폴더 선택`으로 기존 폴더를 고른 뒤 `저장`하세요. 작업실 상단 `설정`에서도 바꿀 수 있습니다.

- 예: `글쓰기/LinkedIn`, `프로젝트/콘텐츠/원고`
- 빈 값: 볼트 최상위에 저장
- 없는 폴더: 새 글을 만들 때 하위 폴더까지 생성
- 변경 범위: 이후 만드는 새 글에만 적용. 기존 원고와 연결 기록은 이동하지 않음

신규 설치의 기본 위치는 `글쓰기`입니다. 기존 `Writing Workbench` 폴더가 있는 설치는 그 위치를 유지하므로 원하는 폴더를 직접 지정하세요. 플러그인 표시 이름은 글결로 바뀌지만 내부 ID와 GitHub 주소는 같아 BRAT에서 기존 플러그인을 업데이트하면 됩니다.

### 화면 조절

세 영역 사이의 구분선을 좌우로 드래그하면 폭을 조절할 수 있습니다. 구분선에 키보드 초점을 둔 상태에서 좌우 방향키를 사용할 수도 있습니다. 두 번 클릭 또는 Home 키로 기본 너비를 복원합니다. 좁은 창에서는 세로 배치로 바뀝니다.

방향 메모는 본문을 두 번 클릭하면 수정할 수 있습니다. 키보드로 항목을 선택한 뒤 Enter를 눌러도 됩니다. 변경한 뒤 `저장`(Cmd/Ctrl+Enter) 또는 `취소`(Esc)를 누르세요.

`글감 찾기`는 기존 인터뷰 기능입니다. AI가 경험과 생각을 하나씩 질문하면서 주제·관점·개요를 찾습니다. 이번 질문은 별도로 강조하고 이전 대화는 접어 둡니다. 원고 검토 결과는 `검토` 탭에서 확인합니다.

수락한 제안에는 `수락 취소`가 표시됩니다. 취소하면 그 제안만 원래 구절로 돌아가며 다시 수락·거절할 수 있습니다. 이후 직접 고친 원고가 있으면 덮어쓰지 않고 안내합니다. 취소도 작업 사본에 반영되므로 연결 파일에는 `원고 저장`으로 저장하세요.

### 수동 설치와 CLI 설정

1. 검증용 Obsidian 볼트를 먼저 준비합니다.
2. `npm run package`로 생성한 `dist/writing-workbench` 폴더를 해당 볼트의 `.obsidian/plugins/` 아래에 복사합니다. 사용자 지정 설정 폴더라면 그 아래 `plugins/`를 사용합니다.
3. Obsidian의 커뮤니티 플러그인 목록을 새로고침하고 글결을 켭니다.
4. 설정에서 CLI 실행 파일을 확인합니다. 자동 탐색이 안 되면 `command -v claude` / `command -v codex`의 경로를 입력합니다.
5. 터미널에서 사용할 CLI의 설치와 로그인을 먼저 완료합니다.
6. 명령 팔레트의 `글결 열기` 또는 `현재 노트를 글결에 연결`을 실행합니다.
7. `새 글` 또는 `글 열기`를 선택하고 인터뷰하거나 초안을 작성합니다.

현재 개발 환경에서 확인한 CLI: Claude Code 2.1.310, Codex 0.164.0. 이전 CLI는 옵션이 달라 호환되지 않을 수 있습니다. 설정의 실행 파일 확인은 경로만 검사하며 로그인·응답 성공을 보장하지 않습니다.

## 데이터와 접근 범위

- 원고는 기존 Markdown 파일입니다. 플러그인이 자동으로 LinkedIn에 게시하지 않습니다.
- 작업 기록은 `<볼트 설정 폴더>/plugins/writing-workbench/state/projects/<id>.json`에 저장됩니다.
- 승인·대기 중 문체 원칙은 `state/preferences.json`에 저장됩니다.
- 화면 너비는 `state/layout.json`에 별도로 저장됩니다. 원고와 CLI 설정은 바꾸지 않습니다.
- JSON 저장 시 직전 버전의 `.bak`을 남깁니다. 손상 복구 시 원본은 `.corrupt-<timestamp>`로 보존합니다.
- 플러그인 폴더를 삭제하기 전 `state/`를 백업하세요. 플러그인 업데이트 시 `state/`와 `data.json`은 유지해야 합니다.
- 선택된 원고, 대화, 메모, 참고 자료는 선택한 AI 제공자로 전송됩니다. CLI 실행 방식이 로컬 모델 실행을 의미하지는 않습니다.
- API 키를 플러그인에 저장하지 않습니다. 기존 CLI 로그인을 사용합니다. 코드 실행·파일 수정 도구는 요청에 제공하지 않습니다.
- CLI를 임시 디렉터리에서 실행하고 응답 처리 후 해당 디렉터리를 제거합니다. 전역 MCP·훅·프로젝트 지시의 자동 로딩을 제한합니다.
- Codex의 사용자 config는 실행 격리를 위해 로드하지 않습니다. 모델은 플러그인 설정에서 지정합니다. 회사 관리 설정은 CLI 자체 정책을 따릅니다.
- 외부 검색을 켠 경우에도 출처의 정확성을 사람이 확인해야 합니다. 미리보기의 피드 접힘 위치는 정확한 LinkedIn 렌더링을 보장하지 않습니다.

## 현재 한계

- 실제 Obsidian UI와 패키지 설치·업데이트 인수 검증은 별도 필요합니다.
- AI 응답은 완료 후 표시합니다. 토큰 스트리밍 UI는 후속 작업입니다.
- 파일 이름 변경은 연결을 갱신합니다. 플러그인이 꺼진 동안 파일을 이동한 경우 복구 작업 기록에서 연결을 다시 확인해야 합니다.
- 모바일 Obsidian, LinkedIn 자동 게시·성과 수집, 자동 장기 기억 학습은 지원하지 않습니다.
- 작업 기록·원고는 볼트의 로컬 파일입니다. 다른 기기의 같은 플러그인 상태 파일을 동시에 편집하는 동기화 시나리오는 미검증입니다.
